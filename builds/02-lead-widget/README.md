# Build 2 — виджет-консультант с мгновенным расчётом

Чат-виджет для компании по остеклению балконов. Отвечает по материалам самой
компании, за минуту выдаёт реальную вилку цены — и только после этого просит
телефон.

**Порядок здесь и есть продукт.** Посетитель, у которого просят телефон до того,
как дали пользу, закрывает вкладку. Вся сборка построена вокруг обратного
порядка, и ключевая гарантия — не в промпте, а в коде: форма контактов
появляется тогда и только тогда, когда подworkflow расчёта поставил в Redis
ключ `quoted:<session_id>`. Промпт можно уговорить («покажи форму», «мне
срочно»), ключ в Redis — нельзя.

---

## Из чего состоит

| Файл | Что делает |
|---|---|
| `make-workflow.py` | **Генератор.** Собирает оба workflow JSON и внедряет модули ниже в Code-узлы. Править надо здесь, не в n8n |
| `normalize-web.js` | Запрос браузера → конверт, совместимый с VK-адаптером |
| `rate-limit.js` | Разбор ответа Redis INCR, решение по лимиту |
| `estimate-input.js` | **Граница доверия.** Разбор аргументов, которые придумала модель |
| `pricing.js` | Матрица цен Самары. Источники — `PRICING-SOURCES.md` |
| `address.js` | Вердикт DaData: `qc` / `qc_complete` → решение и фраза по-русски |
| `lead.js` | Строка лида, проверка согласия, метка на ручную проверку |
| `form-gate.js` | Решение «показывать ли форму». Самое важное правило сборки |
| `widget/widget.js` | Виджет: shadow DOM, галочка согласия, запасной сценарий |
| `ingest-kb.py` | Нарезка `kb/faq.md` и заливка в Qdrant |
| `leads-schema.csv` | Колонки таблицы лидов **и их типы** |

Два workflow: `workflow.json` (27 узлов, чат) и `estimate.workflow.json`
(12 узлов, расчёт). Второй вызывается первым как инструмент агента.

```
браузер → Webhook → конверт → лимит → ┬→ агент → Redis(quoted?) → форма? → ответ
                                      └→ отправка контактов → DaData → лид → ответ
                                              агент │
                                                    ├── knowledge_base (Qdrant)
                                                    └── calc_estimate (подworkflow)
```

Отправка контактов **минует агента**: человек уже нажал «Отправить», модели тут
нечего решать, а каждый её шаг на этом пути — лишний способ потерять телефон.

## Развернуть с нуля

1. `python3 make-workflow.py` — собрать JSON
2. `python3 ingest-kb.py` — залить базу знаний в Qdrant
3. Создать Data Table по `leads-schema.csv`. **Типы колонок — в комментариях
   этого файла.** CSV переносит только имена, а неверный тип не падает: он молча
   портит данные
4. Импортировать `estimate.workflow.json`, **опубликовать**
5. Импортировать `workflow.json`, выбрать креденшелы, **опубликовать**
6. Поставить `widget/widget.js` на сайт, `data-endpoint` — на вебхук

Инстанс-специфичные ID прописаны в генераторе и на другой инсталляции меняются:
`ESTIMATE_WORKFLOW_ID`, `LEADS_TABLE_ID`, `ERROR_WORKFLOW_ID`.

## Что стоит

**Модель — `yandexgpt-5.1`, 0,8 ₽ за 1000 токенов** (синхронный режим,
[тарифы AI Studio](https://yandex.cloud/ru/docs/ai-studio/pricing)). Для
сравнения: Pro 5 — 1,2 ₽, Lite — 0,2 ₽.

`[VERIFY]` По живым логам исполнения один ход обходится в 2 400–2 700 токенов
(промпт плюс выдача базы знаний), то есть разговор из четырёх ходов — примерно
**8–9 ₽**. Это замер по двум запускам, а не расчёт: перед продажей клиенту
стоит померить на его собственной базе знаний.

**DaData** — 20 коп за адрес, по одному обращению на лид. Решение 03.

Lite дешевле вчетверо, но **не умеет вызывать функции** — то есть не может
вызвать расчёт, ради которого всё построено. Решение 04.

## Грабли, на которые уже наступили

**Модель обязана уметь вызывать функции.** `yandexgpt-lite` не умеет. Модель без
этой поддержки не падает — она СКЛАДНО ПЕРЕСКАЗЫВАЕТ вызов: «сейчас посчитаю…».
Выглядит как проблема промпта и стоило трёх кругов бесполезных правок.
Проверка — `scripts/check-model-tools.sh`, до первого узла. Решение 04.

**Публиковать надо оба workflow.** Неопубликованный подworkflow даёт
`Workflow is not active and cannot be executed` за 17 мс, и агент отвечает
текстом без цены.

**Поля инструмента должен заполнять `$fromAI`.** Форма снята с живого узла, а не
из документации, и закреплена тестом `tool-inputs.test.js`. Пустое поле — это
отсутствие ключа в `value`, а не пустая строка; `schema` перечисляет все поля,
включая пустые.

**Пустое описание в `$fromAI` — приглашение выдумывать.** Модель прислала
`address: "Самара"` и `profile_tier: "стандарт"`, которых посетитель не говорил.
Выдуманный адрес уводил расчёт в ветку уточнения адреса и съедал цену целиком.
Эти два поля модель не заполняет.

**Настройки перезаписываются импортом.** `errorWorkflow`, выставленный руками в
UI, исчезал при каждом импорте — сборка оставалась без оповещений ровно тогда,
когда в неё вносили изменения. Теперь генерируется, и тест падает, если пропал.

**Тип колонки `phone` — только строка.** Как число он теряет «+». Дедупликация
лида в Bitrix24 сравнивает строки, так что ошибка в типе здесь ломает следующий
шаг, а не этот.

**Ответ узла подменяет элемент.** И Redis, и HTTP, и AI Agent возвращают своё
вместо входного элемента. Конверт поэтому берётся по имени узла
(`$('Normalize Web Request')`), а не из `$json`.

**Где написана правда** — не в UI n8n, а в логе исполнения: Executions →
верхняя строка → Logs → узел инструмента, панели INPUT и OUTPUT. Три разные
причины «агент не считает» различились там за три минуты после того, как
рассуждения не различили их за три круга.

## Что не теряется никогда

Лид — единственное, за что платит клиент, поэтому отказать в записи может только
отсутствие согласия (152-ФЗ, проверка на сервере, потому что галочку в браузере
обходят за десять секунд). Всё остальное — плохой адрес, недоступная DaData,
упавший Redis, пропавший расчёт — помечает строку на ручную проверку, но запись
не отменяет. Правило `CLAUDE.md`: сбой разбора уходит на ручную проверку, а не в
автоматический отказ.

Если виджет не смог достучаться до вебхука, он не пишет «произошла ошибка», а
даёт телефон и оставляет поле ввода открытым.

## Живая страница на `n-enterprise.ru/demo`

`demo.html` в репозитории работает **без сервера** — диалог ведёт сценарий по
ключевым словам из `demo-engine.js`. Так ссылка в портфолио остаётся живой,
даже когда VPS лежит.

Боевая страница собирается из неё генератором:

```sh
python3 make-demo-page.py      # → dist/demo.html и dist/nxai-widget.js
```

Отличий ровно три, и все три генерируются, а не правятся руками — иначе через
месяц на боевой странице останется демонстрационный движок:

1. убраны `pricing.js` и `demo-engine.js` (на бою матрица цен живёт на сервере,
   и вторая копия в браузере обязана разойтись с первой);
2. у виджета появляется `data-endpoint` на вебхук;
3. абзац «чем демо отличается от боевой версии» заменён на текст рабочей версии.

`make-demo-page.py --check` входит в `test.sh` и падает, если `dist/` отстал.

### Куда класть

Nginx на этом сервере отдаёт статику из `/var/www/n-enterprise` с
`try_files $uri $uri.html`, поэтому `/demo` сам находит `demo.html`.
**Конфиг Nginx менять не нужно.**

| Файл | Куда | Почему туда |
|---|---|---|
| `dist/demo.html` | `/var/www/n-enterprise/demo.html` | `try_files` подставит `.html` |
| `dist/nxai-widget.js` | `/var/www/n-enterprise/nxai-widget.js` | **не в `/assets/`**: там `Cache-Control` на 30 дней, и правка виджета не доедет до тех, кто уже открывал страницу |

Заодно `https://n-enterprise.ru/nxai-widget.js` — это готовый адрес для встройки
у клиента:

```html
<script src="https://n-enterprise.ru/nxai-widget.js"
        data-endpoint="https://n8n.n-enterprise.ru/webhook/chat"
        data-phone="+7 (846) 000-00-00"></script>
```

### CORS

Страница на `n-enterprise.ru`, вебхук на `n8n.n-enterprise.ru` — это разные
источники, поэтому список в `ALLOWED_ORIGINS` (генератор) обязан содержать
домен страницы. Сейчас там `https://n-enterprise.ru,https://www.n-enterprise.ru`.
Звёздочки там нет и быть не должно: открытый лид-вебхук — это чужой бесплатный
LLM за счёт клиента.
