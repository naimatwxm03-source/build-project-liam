# Decision 03 — DaData вместо Яндекс.Геокодера для проверки адреса

**Дата:** 2026-09-14 · **Статус:** принято · **Отменяет:** выбор геокодера в брифе Build 2 · **Правит:** `CLAUDE.md`, «one-account rule»

## Решение

**Адреса проверяет DaData «стандартизация адресов», а не Яндекс.Геокодер.**

## Почему

Геокодер выбирался в брифе с пометкой `[VERIFY] Yandex Geocoder free-tier daily
cap at 200 conv/day`. Проверили. Бесплатного коммерческого тарифа нет.

| | Цена | Что даёт |
|---|---:|---|
| **DaData**, стандартизация адресов | **20 копеек за адрес** — около **2 900 ₽/год** на объёмах брифа | Разобранный адрес, координаты, ФИАС/КЛАДР **и коды качества** |
| **Яндекс.Геокодер**, стандартная лицензия | **195 000 ₽/год** до 1 000 запросов в сутки | Координаты и компоненты адреса |

Бесплатный режим Яндекса действует только при [условиях бесплатного
использования](https://yandex.ru/dev/commercial/doc/ru/): некоммерческое
применение, публичный сайт, видимая карта Яндекса с атрибуцией. Лид-виджет на
сайте платящего заказчика под это не подходит.

Разница в 67 раз — и это за компонент, который **на цену не влияет вообще**.
Районных прайсов у нас нет, наценку по району мы не изобретаем (см.
`builds/02-lead-widget/PRICING-SOURCES.md`), так что адрес нужен ровно для двух
вещей: убедиться, что объект реальный, и передать его замерщику.

## DaData лучше по существу, а не только по цене

Геокодер отвечает на вопрос «где это?». Нам нужен ответ на вопрос «можно ли по
этому адресу отправить замерщика?» — и DaData отвечает на него полем, а не
намёком:

| Поле | Что означает | Как используем |
|---|---|---|
| `qc = 2` | адрес пустой или мусорный | переспросить |
| `qc = 3` | есть варианты («Москва, Тверская-Ямская» — их четыре) | переспросить, назвав неоднозначность |
| `qc_complete = 4` | **нет номера дома** | попросить номер дома |
| `qc_complete = 3` | нет улицы | попросить улицу |
| `qc_complete = 7` | иностранный адрес | честно сказать, что не наш регион |
| `fias_level = 8` | дом найден в ФИАС | можно считать |
| `region` | регион | проверка зоны выезда |

С Геокодером всё это пришлось бы выводить из координат и полноты ответа —
писать эвристику там, где сервис отдаёт готовый вердикт. Это лишний код,
который сломается на первом нестандартном адресе.

## Чем это платим

- **Ещё один поставщик и ещё один счёт.** Правило одного аккаунта из
  `CLAUDE.md` нарушено сознательно: оно существует ради простоты, а не ради
  Яндекса как такового. Экономия 192 000 ₽/год оправдывает второй счёт.
- **Два секрета вместо одного.** DaData для метода `clean` требует и API-ключ,
  и секретный ключ. Оба — в креденшелы n8n, ни один — в workflow.
- **Нельзя вызывать из браузера.** Секретный ключ утечёт. Вызов только с
  сервера, из n8n. Для нашей архитектуры это и так верно.

## Поправка к CLAUDE.md

Формулировка «LLM, Vision OCR, SpeechKit и Geocoder приходят из одного аккаунта
Yandex Cloud» неверна в части геокодера по двум причинам:

1. Ключ Геокодера выдаётся не в консоли Yandex Cloud, а в **Кабинете
   разработчика** (`developer.tech.yandex.ru`) — другой портал, другой счёт.
2. **С 12.05.2026 Яндекс разделил JavaScript API и HTTP Геокодер** на разные
   продукты, один ключ их больше не покрывает.

Остальная часть правила (LLM, Vision, SpeechKit) остаётся в силе.

## Что осталось непроверенным

- `[VERIFY]` Есть ли у DaData бесплатная квота на метод `clean`. На странице
  тарифов указано только «20 копеек за запись»; возможен стартовый баланс при
  регистрации. Не закладываем: 2 900 ₽/год и так не меняют экономику сборки.
- `[VERIFY]` Лимит 20 запросов в секунду с одного IP. На 200 разговорах в сутки
  запас огромный, но для клиента с высоким трафиком проверить перед продажей.
